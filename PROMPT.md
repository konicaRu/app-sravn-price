# Промпт для разработки приложения «Выгодно?»

Ты senior frontend/PWA инженер, UX-дизайнер и специалист по OCR. Разработай рабочее мобильное PWA «Выгодно?» для сравнения стоимости сопоставимых товаров в российских магазинах. Интерфейс полностью на русском языке, валюта только RUB. Нужен полный исходный код, инструкции по запуску, сборке и HTTPS-размещению; не макет. Без регистрации, сервера, базы данных, платных OCR/API и обязательных облачных сервисов.

## Приоритет сценариев
1. На первом месте **ручной ввод**: поле «Вес / объём / количество», селектор г/кг/мл/л/шт, поле «Цена, ₽», кнопка «Добавить товар». Название товара необязательно. Пользователь может последовательно добавлять до 5 товаров, удалять их и изменять любые данные.
2. Второй способ — **фотографирование**: одна фотография = один ценник. Поддержи камеру и выбор фото из галереи. Не делай мультиценниковый поиск в MVP. Можно смешивать ручные и фото-товары в одном сравнении.
3. После каждого добавления по фото возвращай на основной экран со списком, а не открывай камеру снова. Основной экран один, список товаров и результат на нём.

## Расчёты
- При одном товаре автоматически показывай цену за 1 кг, 1 л либо 1 штуку.
- При 2–5 сопоставимых товарах автоматически, без кнопки «Рассчитать», покажи рейтинг, стоимость единицы, самый выгодный вариант и процент экономии относительно наиболее дорогого за единицу: `(max_unit_price - min_unit_price) / max_unit_price * 100`. Показывай также полную цену покупки.
- Нормализуй г↔кг, мл↔л, шт↔шт; **никогда автоматически не приравнивай массу к объёму** и не сравнивай несопоставимые группы: показывай понятное предупреждение.
- Входные значения >0, десятичная запятая и точка, защита от NaN и деления на ноль, аккуратное округление только для отображения, вычисления на исходной точности.
- Максимум 5 товаров. Кнопку добавления отключай по достижении лимита.
- Мультиупаковки (например, 6 × 0,5 л) в MVP **не поддерживать**.

## OCR фотографий
- Бесплатное OCR локально в браузере, например Tesseract.js с `rus+eng`; не пересылай изображения внешним API. Предусмотри понятный статус загрузки языков, прогресс, ошибки, вариант исправить всё вручную. Допускается первая загрузка OCR-моделей по сети; чётко сообщи об этом.
- Распознавай название товара, вес/объём, обычную цену, акционную цену/по карте, характеристики (когда указаны), и напечатанную магазином цену за кг/л/100 г, если есть.
- Нельзя считать OCR безошибочным: показывай форму проверки с миниатюрой фото (по нажатию увеличить) и **всеми редактируемыми полями**. Неуверенные или отсутствующие поля подсвечивай, не выдумывай значения.
- Если обнаружены обычная и акционная цена, **для каждого товара отдельно** пользователь выбирает используемую цену. При единственной цене выбирай её автоматически.
- Сопоставляй самостоятельно рассчитанную цену за единицу с напечатанной магазином, когда это можно надёжно установить. При существенном расхождении предупреждай, не заменяй рассчитанную цену автоматически; учитывай округление и возможную разницу цены по карте.
- По возможности учитывай поворот фото/масштаб/контраст, но важнее работоспособный MVP. Автоматическое распознавание одного ценника не равно детектору нескольких ценников.

## Сопоставимость характеристик
- Сравнивай распознанные характеристики товаров и предупреждай **только о существенных различиях**: жирность 2,5% против 3,2%, сливочное масло против спреда, кефир против молока, растворимый против молотого кофе и аналогичные различия. Разные бренды сами по себе не причина для предупреждения.
- Реализуй объяснимые локальные правила без платной языковой модели, явно укажи, что они не гарантируют полноты. При неизвестных характеристиках предложи необязательное ручное заполнение и не утверждай, что товары идентичны.
- В предупреждении укажи точную причину различия. Дай действия «Всё равно сравнить» и «Убрать товар». Предупреждения не должны навсегда блокировать математический расчёт.
- Сохраняй распознанный исходный текст отдельно от редактируемого названия для диагностики OCR.

## Удобство, хранение, отправка
- Светлый минималистичный адаптивный UI с зелёным акцентом у наиболее выгодного товара, крупные поля/кнопки для использования в магазине. Без сложной навигации.
- Незавершённый список товаров сохраняй **локально на устройстве**, после перезапуска восстанавливай. Фото храни только в течение активной сессии сравнения и очищай при её завершении. Учитывай ограничение: после закрытия вкладки черновик может сохраниться без миниатюр.
- Кнопка «Очистить / Новое сравнение» с защитой от случайной потери данных.
- Поделиться результатом текстом через Web Share API (или копирование в буфер) и картинкой PNG через Web Share API (или скачивание).
- Работоспособность на Android и iPhone, PWA manifest, service worker для оболочки, установка на главный экран при размещении на HTTPS. Не обещай автономную работу OCR, если языковые модели и worker не кешируются локально.
- Доступность, контрастность, мобильная клавиатура для чисел, логичные подписи, безопасность пользовательского текста (избегать XSS), обработка ошибок и чистый код.

## Проверка качества
Протестируй: 900 г/110 ₽ против 1 кг/115 ₽; 900 мл против 1 л; 2 и 5 товаров; 1 товар; обе цены (обычная/по карте); неверный OCR; нет веса/цены; 2,5% против 3,2%; разные единицы масса/объём; 0, пустые поля, десятичную запятую; сохранение после перезапуска; ручной и фото ввод одновременно; отправку текста и PNG. Покажи структуру проекта и команды запуска.

Результат: предоставь все файлы проекта и короткую инструкцию для размещения на HTTPS-хостинге и установки PWA на смартфон. Не ограничивайся рассказом о том, что нужно сделать.
